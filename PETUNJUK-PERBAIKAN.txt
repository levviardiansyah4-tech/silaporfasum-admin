PERBAIKAN SiLaporFasum Admin

Yang diperbaiki di admin.js:
1. Foto dari bucket privat `foto-laporan` sekarang memakai signed URL baru (berlaku 1 jam), bukan getPublicUrl.
2. URL foto yang tersimpan sebagai URL Supabase penuh atau path bucket/file ditangani.
3. URL foto diperbarui saat data laporan dimuat dan setelah perubahan laporan disimpan.
4. Pesan error penyimpanan status dibuat lebih jelas jika tidak ada baris yang diperbarui.

CARA PASANG
1. Ekstrak ZIP ini.
2. Upload/replace file dalam folder `silaporfasum-admin.-main` ke tempat hosting admin (termasuk admin.js dan index.html/css bila hosting menyimpan satu folder).
3. Hard refresh browser: Ctrl+Shift+R (Windows) atau Cmd+Shift+R (Mac), lalu login lagi.

CATATAN SUPABASE
- Bucket `foto-laporan` adalah private. Membuat signed URL memerlukan sesi login dan policy SELECT pada `storage.objects` yang mengizinkan akun admin membaca objek bucket `foto-laporan`.
- Jika foto masih gagal, buka Console browser. Pesan `URL foto laporan tidak dapat dibuat` biasanya berarti policy Storage atau path file tidak cocok.
- Jika status gagal disimpan dan muncul pesan tidak ada baris yang diperbarui, cek policy RLS UPDATE dan SELECT pada tabel `public.laporan` untuk akun admin serta pastikan ID laporan cocok. Kode frontend tidak dapat mengubah policy database.
- Jangan membuat policy UPDATE/SELECT terbuka untuk semua pengguna tanpa pembatasan peran.


5. PERBAIKAN FITUR HAPUS
- Buka Supabase Dashboard > SQL Editor.
- Buka file SQL_PERBAIKAN_HAPUS.sql dari ZIP ini, salin seluruh isinya, lalu jalankan (Run).
- SQL membatasi DELETE hanya untuk pengguna login dengan email admin@gmail.com. Jika email admin yang dipakai berbeda, ubah email di SQL terlebih dahulu.
- Pastikan akun admin juga memiliki policy SELECT pada public.laporan agar aplikasi bisa memverifikasi penghapusan.
- Setelah itu login ulang ke halaman admin dan tes hapus satu laporan uji.


PEMERIKSAAN JIKA MASIH GAGAL
- Klik Hapus lalu lihat email login yang tampil pada pesan error.
- Email tersebut harus sama dengan email yang diizinkan pada SQL_PERBAIKAN_HAPUS.sql (default: admin@gmail.com).
- Pastikan SQL dijalankan pada project Supabase yang sama dengan URL di admin.js.
- Jika email terdeteksi berbeda, ubah email di kedua policy SQL, jalankan ulang SQL, lalu login ulang ke website admin.
